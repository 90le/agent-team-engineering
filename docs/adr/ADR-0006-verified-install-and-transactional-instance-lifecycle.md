# ADR-0006：可验证安装与事务化实例生命周期

- 状态：Accepted
- 日期：2026-08-10

## 背景

v0.2建立实例锁和文件所有权，v0.3增加持久运行状态，v0.4增加外部适配器边界，但仍缺少两个关键闭环：采用者无法把某个Factory发布安装成自证完整的执行副本，实例也无法在跨版本变化时区分安全升级、普通relock和失败后的恢复。仅依靠复制目录、检出分支或“先备份再覆盖”无法绑定精确来源，也不能处理进程在多文件切换中间退出。

已有项目接入同样需要明确写权限边界。若发现工具在目标仓库写入文件或隐式刷新Git索引，“接入提案”就不再是可证明的只读动作。

## 决策

1. 正式Factory安装只接受干净、精确指向版本的annotated tag。安装副本使用 `.factory-installation.json` 绑定发布提交、标签、逐文件路径/模式/大小/SHA-256及整树摘要；安装和验证拒绝覆盖、符号链接、额外文件与派生缓存。
2. Doctor产生严格JSON报告，区分 `PASS`、`WARN`、`FAIL`，同时诊断Factory来源、契约、POSIX生命周期锁、实例锁/漂移、事务日志及SQLite审计；它不把本地静态检查解释成外部服务健康证明。
3. `relock`只接受同一Factory下经过验证的声明式配置变化，不承担版本迁移。升级必须通过目标发布中显式列出的源版本、摘要绑定计划和独立人工审阅。
4. 升级前必须停止外部Writer并证明运行库静止。数据库暂停是必要状态之一，不是进程已停止的证明。
5. 升级先在实例外创建权限受限、清单自校验的恢复包，再在实例内建立持久生命周期日志。managed文件只在当前摘要等于旧锁时变化；seeded自定义原样保留；目标锁最后写入，作为逻辑提交标记。
6. 升级和主动回滚共用同一事务日志。回滚先创建当前版本救援包。进程中断时，恢复命令根据日志回到该操作开始前版本；第三方漂移、包篡改或身份不匹配时安全停止。
7. 生命周期互斥使用POSIX `fcntl` 非阻塞锁。当前不提供语义较弱的跨平台回退，也不宣称该锁能终止未遵守Factory协议的进程。
8. 项目发现设置 `GIT_OPTIONAL_LOCKS=0`，提案和候选配置只能原子写到目标仓库外。提案逐文件摘要绑定且永久标记为 `proposal-only`；组合操作不启用适配器、不提升自治或授予外部权限。

## 后果

采用者可以从受信Git发布得到可重复验证的Factory安装，并能在v0.2、v0.3、v0.4实例到v0.5的迁移中预览变更、保留自定义、故障恢复和双向回退。生命周期失败会暴露为日志和验证失败，而不是允许混合版本继续运行。

代价是每次迁移需要维护窗口、人工计划审阅、外部恢复存储和显式迁移路径；Windows不能执行当前生命周期写操作。多文件切换实现的是“锁最后提交、未知状态拒绝”的逻辑原子性，不是文件系统级多文件原子事务。恢复包只覆盖Factory转换文件，运行数据库、目标项目、秘密和外部提供者状态仍需各自的备份、对账与恢复流程。annotated tag绑定Git对象类型，但不替代签名或仓库信任链。
