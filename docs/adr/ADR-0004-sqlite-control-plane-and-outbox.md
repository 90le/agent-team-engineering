# ADR-0004：SQLite控制平面与事务outbox

- 状态：Accepted
- 日期：2026-08-10

## 背景

参考模拟器在进程结束后丢失状态，不能抵抗重复投递、并发Agent、Worker崩溃或“状态已提交但外部副作用未执行”的部分失败。第一版Factory需要在单机和小团队环境中提供依赖少、可复制和可恢复的持久基线，同时不能提前绑定某个云任务引擎。

## 决策

1. v0.3使用Python标准库SQLite作为单实例参考控制平面，启用外键、WAL、busy timeout和FULL同步。
2. 工作项继续使用乐观 `revision`；非owner转换还必须持有匹配工作项、身份、角色、修订和期限的持久租约。
3. 每个可重试入口使用稳定幂等键和请求摘要；相同键绑定不同请求时拒绝。
4. 外部副作用使用与控制状态同库的事务outbox。Worker领取有期限，失败重试有上限，耗尽进入`DEAD`。
5. 所有控制变化进入连续序列与SHA-256前向哈希链。哈希链用于检测非预期篡改，不冒充外部签名或防恶意管理员重写。
6. 全局暂停阻止新状态转换和新副作用领取，但允许记录已经发生的效果结果、对账、验证和备份。
7. 数据库是运行状态，不进入普通Git；使用SQLite在线备份API创建一致副本，恢复只允许到不存在的新路径。
8. v0.3不宣称多节点高可用。需要跨主机并发、远程数据库或工作流引擎时，必须保持开放契约并另立ADR。

## 后果

单机环境可以在进程重启和有限并发下安全恢复，部署前提保持很小。代价是运行数据库需要独立备份、权限和监控，且SQLite不能直接放到锁语义不可靠的网络共享目录。外部副作用仍可能出现“提供者成功、Worker确认前崩溃”，所以v0.4适配器必须把outbox幂等键传给提供者或执行对账。

本机CLI只位于受控操作系统权限边界内，不提供远程身份认证。`kind=human` 是核心授权声明而非身份凭证；真实审批适配器必须验证并绑定人工身份、批准对象和有效期，才能安全地向核心提交该声明。
