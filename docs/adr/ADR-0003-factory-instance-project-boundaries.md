# ADR-0003：Factory、实例与项目边界

- 状态：Accepted
- 日期：2026-08-10

## 背景

通用多智能体工程需要持续升级，而每个采用者的平台绑定、批准人、项目和运行状态具有不同权限与生命周期。把三者混在同一个仓库会让升级覆盖私有配置，也会让通用代码无法安全复用。

## 决策

1. Factory仓库拥有通用契约、控制平面、CLI、团队包、Skill、适配器接口、模板和迁移。
2. 每个长期团队拥有独立Private实例仓库，保存非秘密声明、版本锁、策略覆盖、项目绑定、运维文档和验收证据。
3. 业务仓库继续拥有产品事实、架构、源码、测试和发布历史；实例通过受限适配器引用，不复制其权威内容。
4. 实例锁定具体Factory和团队包版本。升级只通过显式计划和迁移发生，不追随Factory的默认分支。
5. 运行数据库、模型会话、Runner工作区、制品和秘密不进入上述普通Git仓库。
6. Factory在v1.0前保持单仓库；只有形成独立发布周期和稳定API后才能另立ADR拆分。

## 后果

Factory可以独立发布和审查，实例可以保持Private并按自己的节奏升级，业务项目也不需要复制团队实现。代价是必须维护跨仓版本锁、迁移和冷启动验证。
