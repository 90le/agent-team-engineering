# Guided adoption FAQ

## Is this a multi-agent framework?

It is a vendor-neutral team factory and governance core. It creates the context, roles, Skills, workflows, handoffs, platform entrypoints and optional governed controller that Codex, Claude, OpenClaw or another host can operate. It is not a new model provider or chat transport.

## Why does the guide not ask me to choose Lite, Managed or Custom?

Those names are compiler mappings that mix implementation details. The product decision is what the team should do, whether work must persist automatically, and which AI products consume it. The guide translates those answers into the mapping and explains it afterward.

## Does the generated team immediately run by itself?

The file-based team is immediately readable and usable through an AI host. Managed packages also include the governed reference controller. Live model accounts, feedback channels, authenticated approval, GitHub writes and an isolated Runner still require explicit adopter integration and remain disabled by default.

## Can it create non-software teams?

Yes. Research/knowledge, content and operations purposes receive starter role sets, and `custom` accepts arbitrary named roles. These teams begin context-only. Durable external automation for custom roles requires a separate capability mapping.

## Why is Python present if context engineering is based on Markdown?

Markdown and Skills carry long-lived meaning. Python enforces properties prose cannot: strict schemas, deterministic output, digest-bound confirmation, non-overwrite behavior, revisions, recovery and security-negative tests. Generated file-based teams do not need a persistent Python process.

## Can I use more than one AI product?

Yes. Select multiple platforms and they receive thin native adapters over the same shared context. They do not become separate sources of truth.

## Does confirmation approve GitHub, OpenClaw, merge or deploy access?

No. The first guided confirmation authorizes only creation of one named new local team directory. A second exact confirmation can authorize only the files in a host-package plan. Native activation, project reconciliation, live integrations, merge and deployment remain separate gates.

## Where should the generated team live?

Use a new directory outside both the Factory and target project. It may become its own private Git repository when it spans projects or needs an independent lifecycle. Generate a host package into another reviewed destination; reconcile it into a real project or live host only under that project's normal review and a separate authorization.

## How do I ask for help?

Use GitHub Discussions for adoption and architecture questions. File an Issue for a reproducible bug or a scoped feature proposal. Do not include credentials, private repository content, user data, or production logs.
