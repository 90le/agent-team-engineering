# v0.9.0 release acceptance

v0.9.0 is accepted only when the repository behaves as a host-native Agent Team Factory: a human or no-history AI can discover a project and locally installed AI hosts, recommend a team in user language, create one locked portable authority after an exact confirmation, and separately install a non-overwriting native projection after a second exact confirmation.

The immutable recovery baseline is annotated `v0.8.1` at `d6cf371c2f78aa230965720206514d3fe8142b75`.

## Product calibration

The Factory is not itself a mandatory multi-agent runtime. Its primary output is a portable authority package—Markdown, JSON, Skills, roles, workflows, decisions and a lock—plus a projection shaped for an AI host the user already operates. The existing restart-safe Managed controller remains an optional execution layer for governed feedback-to-Draft-PR work.

The evidence supplied for this release supports that calibration. It repeatedly asks how an existing project, experience and constraints become a native team in another Agent product. It does not establish an authoritative product identity for “Leda”; v0.9 therefore records that name as `research-unknown` instead of guessing.

## Two independent approvals

1. Team adoption: `onboard plan → preview → confirm → apply` creates a new locked team outside both the Factory and target project.
2. Host installation: `host plan → preview → confirm → apply` copies only the proposal's absent files into one exact destination and writes an installation lock.

Neither approval authorizes authentication, live host object creation, channel bindings, model calls, issue or pull-request writes, background workers, merge, release, or deployment. A native CLI import or activation is a third, host-specific authorization.

## Host lifecycle safety gates

- descriptors are strict data, have immutable support claims, and permit only isolated `--version` or `version` probes;
- probes receive a credential-free environment, no stdin, no shell, a root working directory and a short timeout;
- the first plan embeds and binds the exact Team Design, preset digest, Factory version, and Factory contract digest; apply never recompiles an approved preset name;
- host plans bind the team design, context lock, complete host descriptor digest and tier, destination, every source path and every SHA-256 digest;
- apply rejects stale source, wrong digest, symlinks, path escape, secrets, pre-existing managed paths and unconfirmed plans;
- interruption leaves an `APPLYING` lock and resumes only the identical plan whose existing files still match;
- replay is idempotent; verify detects drift; uninstall requires the exact installation digest and removes only unchanged managed files;
- unrelated files in an existing destination survive both installation and uninstall.

## Rollback

The Factory can return to immutable `v0.8.1`. A v0.9 host installation must first be verified, then uninstalled with the exact recorded proposal digest; drifted files are preserved and require human reconciliation. Existing Team Instances use their external recovery bundle and standard lifecycle rollback. Never move a tag, delete an installation lock to force removal, or reuse an earlier approval digest.
