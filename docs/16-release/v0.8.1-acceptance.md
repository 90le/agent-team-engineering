# v0.8.1 release acceptance

v0.8.1 is accepted only when the scenario-first public experience, deterministic adoption contract, generated-team handoff, legacy compatibility, supply chain, and remote release binding all pass together.

## Scope

This patch changes adoption navigation and generated context. It does not authorize a real Team Instance, production OpenClaw channel, model account, business-repository writer, long-lived Runner, automatic merge, release, or deployment.

The immutable recovery baseline is annotated `v0.8.0` at `9b5df61828cc4256db0a8bdc635c69ce0fb31814`.

## Public adoption gates

- The first README screen states the user problem, outcome and exact start path without requiring a preset choice.
- English and Chinese prompts tell a no-history AI to inspect read-only, ask at most three high-impact questions, recommend and explain, preview, wait for confirmation, create, validate and teach.
- The bundled Codex/Claude/OpenClaw-compatible Skill is self-contained and carries the same conversation contract.
- GitHub description, topics, Discussions, license and release metadata agree with the public positioning.

## Plan and safety gates

- `onboard inspect` is read-only and emits only secret-safe project discovery.
- `onboard plan` writes one strict draft outside the target and Factory.
- `preview` exposes recommendation, alternative, limitations, unknowns, effects and exact digest.
- `apply` rejects an unconfirmed plan.
- Confirmation rejects the wrong digest; proposal tampering invalidates identity and confirmation.
- Source-commit drift, credential-like content, symbolic links, unsafe paths and existing outputs fail closed.
- Successful apply leaves the target project byte-for-byte unchanged and creates no external effect.
- Team creation and project export remain separate confirmation scopes.

## Generated-team gates

- Every new context team contains `GETTING-STARTED.md` and an expanded `AI-START.md`.
- A user can start a task, ask status, continue from durable state, request role explanation, or stop safely without memorizing role IDs.
- Lite, Managed and Custom compilation remains deterministic and validates against context and legacy locks.
- Platform export carries the human and AI entrypoints with the shared authority context.

## Scenario and blind-AI gates

No-history forward tests cover:

1. existing software plus Codex/Claude assisted collaboration;
2. persistent feedback through exact human approval to a tested, independently reviewed Draft PR, with live adapters disabled;
3. a long-lived research/knowledge team with custom evidence roles and no invented Managed authority.

Each tester must find the entrypoint, avoid an opening preset question, inspect before asking, limit questions, explain a recommendation and alternative, stop at preview, preserve external boundaries, and provide a usable first-task handoff.

## Regression and release gates

- repository structural and secret validation;
- all unit, security and CLI tests;
- root and bundled Skill validation;
- Codex and Claude plugin-manifest validation;
- deterministic simulation and Native invariant verification;
- cross-AI takeover and clean-clone cold start;
- version/SBOM/provenance/history release audit relative to `v0.8.0`;
- exact annotated-tag release smoke;
- pull-request and merged-main GitHub Actions;
- annotated `v0.8.1` tag, matching GitHub Release and uploaded evidence;
- anonymous exact-tag clone/install/Doctor/team-creation smoke.
