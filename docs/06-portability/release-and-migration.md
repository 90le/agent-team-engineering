# 发布、复制与迁移

## 可移植发布必须包含

- 完整 Git 历史、版本标签和源提交。
- `AI-BOOTSTRAP.md`、协议 Schema、团队包、Skill 和适配器。
- 验证工具、锁定的运行前提和迁移说明。
- 外部环境、秘密、资产和运行状态的清单，但不包含秘密值。
- SHA-256 清单和空目录恢复证据。

## 新设备恢复

1. 克隆经过验证的版本标签或 Git bundle。
2. 运行 `doctor`、`validate`、单元测试和冷启动。
3. 读取统一入口，选择团队包和平台适配器。
4. 重新创建独立的秘密引用和最小权限身份。
5. 连接一个测试仓库并运行模拟模式。
6. 验证阻止越权的负例后，才启用真实外部写操作。

复制运行数据库、会话缓存或向量索引不是迁移前提；这些内容必须可从开放文件和审计源重建。生产控制器若使用持久数据库，应另有备份、恢复和版本迁移方案。

## 版本升级原则

- PATCH修复不改变现有契约；MINOR增加向后兼容能力；不兼容契约需要MAJOR、ADR和显式迁移。
- `v0.x` 仍可能快速演进，但已发布标签、锁文件和迁移前备份同样不可省略。
- 实例锁定具体Factory版本，不跟随 `main`。运行新Factory验证旧实例只表示兼容性检查，不等于已经升级。
- 升级命令必须先输出文件、Schema、策略和运行状态影响，再建立恢复点；没有回退或验证失败时禁止切换。
- Factory降级不能删除新版本创建的实例或状态。旧工具无法理解新格式时只允许只读保留并要求使用匹配版本恢复。

各版本新增能力、限制和精确回退见仓库根目录 [CHANGELOG](../../CHANGELOG.md)。
