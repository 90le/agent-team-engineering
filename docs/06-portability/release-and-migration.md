# 发布、复制与迁移

## 可移植发布必须包含

- 完整 Git 历史、版本标签和源提交。
- `AI-BOOTSTRAP.md`、协议 Schema、团队包、Skill 和适配器。
- 验证工具、锁定的运行前提和迁移说明。
- 外部环境、秘密、资产和运行状态的清单，但不包含秘密值。
- SHA-256 清单和空目录恢复证据。

## 新设备恢复

1. 从受信远程克隆经过验证的annotated版本标签或验证Git bundle。
2. 在干净标签工作树运行 `factory install --output <new-path>`，再在安装副本运行 `factory verify` 和 `doctor`。不要把开发工作树直接当长期安装目录。
3. 在源码克隆运行 `validate`、单元测试和冷启动，保存提交、标签和证据。
4. 读取统一入口，选择团队包和平台适配器。
5. 重新创建独立的秘密引用和最小权限身份。
6. 恢复实例仓库，再把经过验证的SQLite备份恢复到实例配置路径；不要把运行库加入Git。
7. 连接一个测试仓库并运行模拟模式。
8. 验证阻止越权的负例后，才启用真实外部写操作。

会话缓存和向量索引不是迁移前提；这些内容必须可从开放文件和审计源重建。SQLite运行数据库是独立Private资产，需要verified backup、加密异地副本和恢复演练。Factory实例恢复包只含一次版本切换涉及的受控文件，不能替代运行数据库、目标仓库或整机备份。

## 版本升级原则

- PATCH修复不改变现有契约；MINOR增加向后兼容能力；不兼容契约需要MAJOR、ADR和显式迁移。
- `v0.x` 仍可能快速演进，但已发布标签、锁文件和迁移前备份同样不可省略。
- 实例锁定具体Factory版本，不跟随 `main`。运行新Factory验证旧实例只表示兼容性检查，不等于已经升级。
- 升级命令必须先输出摘要绑定计划，经人工审阅后在实例外建立权限受限恢复包；没有回退、Writer未停止、运行状态不静止或验证失败时禁止切换。
- Factory降级不能删除新版本创建的实例或状态。旧工具无法理解新格式时只允许只读保留并要求使用匹配版本恢复。

v0.5的精确安装、事务日志、恢复和回滚协议见[安装、升级与接入](../11-lifecycle/installation-upgrade-and-adoption.md)。

各版本新增能力、限制和精确回退见仓库根目录 [CHANGELOG](../../CHANGELOG.md)。
