# Verify Release

For an Agent Team Engineering v1.0 release, read `AI-BOOTSTRAP.md` and `docs/16-release/v1.0-acceptance.md` completely. The acceptance document is a required-gate contract, not proof that remote work is finished.

1. Use a clean, isolated Runner without production secrets, production data mounts, PVE/NAS paths, or Docker Socket access.
2. Check out the exact reviewed commit and execute repository validation, all unit/security/contract tests, Skill and plugin validation, cross-AI takeover, release audit from `v0.9.0` with external evidence required, cold start, and simulated exact-tag release smoke.
3. Verify WriterTopology's exact three-digest chain and both false boundary fields. Offline `identity_or_signature_verified: false` means the command does not authenticate an approver or verify a signature.
4. Verify host lifecycle crash/replay, legacy-lock, uninstall-preview, tombstone, non-overwrite, drift, and negative safety gates. Verify explicit `0.9.0 → 1.0.0` instance upgrade and rollback evidence separately from host installation.
5. Record commands, exact commit, Runner identity, timestamps, exit codes, immutable artifact digests, rollback material, and evidence references without leaking sensitive output.
6. Require external SCM first-run/replay evidence bound to the exact protected implementation. Record both sanitized reports together in one evidence-only direct-child commit that changes exactly those two files; protect the two reports and the candidate aggregate from every later mutation. Reject stale evidence after any protected path changes; no merge or deployment may occur.
7. Read the complete required-check set from the effective `main` branch protection/ruleset and require exact equality with the immutable v1 policy: `conformance` and `validate`, both from GitHub Actions App ID `15368`. Policy drift requires a new reviewed release contract and must never silently redefine v1. Require every requested check as `{name, url, app_id}` and every final-evidence check as `{name, url, app_id, completed_at}` for both the exact PR head and accepted `main` commit. A positive `app_id` binds the exact App, `-1` explicitly allows any App check run, and `null` is the API's unbound/automatic source value that may select a check run or legacy commit status; reject simultaneous same-name evidence from both source kinds as ambiguous. Require the merged PR base to be this repository's `main` and the accepted commit to be the current `refs/heads/main` tip. Reject a missing/extra required identity, wrong App, skipped/failed/late check, advanced main, or one-URL substitute. Require an annotated `v1.0.0` tag whose embedded name and peeled commit match, a passing tag workflow, and a matching non-draft GitHub Release.
8. Keep technical review and owner approval separate. Use the read-only OpenClaw reviewer `ate-3df2c143-independent-reviewer` and exact runtime `openclaw/relay/gpt-5.6-sol`; do not use the retired GitHub Models service. Seal the strict review input through the private review workflow pinned at `5dd269b0015b576bad3b85cc358d75d8ed205ed6`, which must rerun deterministic gates and recompute the public patch digest without model or source-repository write permission. The publication finalizer must independently clone the public repository at the exact PR head, reconstruct the fixed-scope `v0.9.0..HEAD` patch, reconstruct the canonical review rubric and unsealed input, and require all three SHA-256 digests to match the sealed artifact. Download strict review JSON from the exact `https://github.com/90le/agent-team-v10-review-private/actions/runs/<id>` run; bind its SHA-256, exact PR head/tree, review workflow commit, OpenClaw Agent/session, prompt/patch digests, `reviewer_kind=independent-ai`, runtime, and `decision=PASS`. Review generation and workflow completion must predate merge. It is not authenticated human approval, a signed model attestation, or an independently authenticated OpenClaw session. Separately require an exact-head GitHub `User` review from repository owner `90le` (user ID `68719118`) with `reviewer_kind=github-user` and `decision=APPROVED`; the approval cannot replace the technical artifact.
9. Keep the two machine-evidence stages separate. The tag workflow may emit only schema `2.1.0` `TAG_WORKFLOW_EVIDENCE` with `PARTIAL` / `NOT_PUBLISHED`; it must leave PR and merged-main check arrays empty, technical review, owner approval, its own completion, artifact upload/download, Release and anonymous-install facts/gates `NOT_RUN`. Never edit or promote that artifact in place.
10. After publication, use `tools/release_publication.py` from a reviewed copy with minimum read-only GitHub access and an external request file. The credential needs public-repository PR review, branch-protection/ruleset, checks/statuses, commit, Actions, tag and Release reads, plus private review- and SCM-evidence-repository Actions/contents reads; the finalizer performs GET requests only. Verify live PR/ruleset/check/review/main/tag/workflow/Release facts, download and digest-check the technical-review artifact, then download the exact non-expired tag-run artifact. Requery both private SCM runs and require each downloaded artifact report byte-for-byte equal its reviewed tagged copy. Require artifact ID, URL, service SHA-256 digest, creation/expiry and retention, plus verified archive, `SHA256SUMS`, tag-evidence, v10, SBOM, provenance and both SCM-report digests. Metadata without a successful bounded download is `NOT_RUN`, not `PASS`.
11. Let the finalizer itself re-run the exact-tag clone over unauthenticated public HTTPS, Factory install/verify/Doctor, team creation, disposable host lifecycle/replay-safe uninstall, and writer-authority validation. It must use a literal minimal subprocess environment allowlist, inherit no caller credentials, disable global/system Git credential configuration and prompting, and record `unauthenticated_git_transport=true`, `caller_credentials_inherited=false`, `same_uid_filesystem_isolated=false`, `write_isolation=false`, and `external_writes_verified=false`. This proves only the transport and environment-inheritance boundary: it is not an OS sandbox or global write monitor, and same-UID candidate code may read or write accessible paths or inspect `/proc`. Use a dedicated credential-free user or disposable isolated Runner when strong isolation is required. A supplied installation claim is insufficient.
12. Write the resulting `FINAL_RELEASE_INDEX` outside every Factory checkout. It may say `ACCEPTED` / `RELEASED` only when all 21 gates are `PASS` and every identity binds the same commit, annotated tag object and workflow artifact. It is an unsigned observation record, not standalone proof: require `standalone_tamper_evident=false`, `cryptographically_authenticated=false`, preserve the original artifacts/request/command evidence, and requery GitHub or use a separately managed signature/transparency log when later authenticity must be proved. Do not modify the tagged source, create/move tags, publish a Release, or perform a GitHub write from the finalizer.
13. Confirm GitHub Actions remain pinned by full SHA and release artifact upload uses the reviewed `actions/upload-artifact` v7.0.1 commit with Node 24.
14. Record every gate as `PASS`, `FAIL`, or `NOT_RUN` with its URL or digest. Missing remote identity, incomplete required-check set, missing/mismatched technical evidence, absent owner approval, failed/other-commit workflow, duplicate or expired artifact, skipped download, checksum mismatch, authenticated/local-clone substitution, or missing evidence is never inferred `PASS`.

Do not waive failures, mutate source while verifying, use author-supplied success claims as sole evidence, move a tag, rebuild an artifact from another commit, or approve production. Stop on a failed, flaky, skipped, stale, identity-mismatched, provenance-incomplete, or rollback-incomplete gate. This Factory release process does not itself deploy a user project.
