# Example: durable feedback to a reviewed Draft PR

## User request

> Collect user feedback, deduplicate and analyze it, let me approve the exact plan, then keep development, testing and independent review moving across restarts until a Draft PR is ready.

## Focused questions

1. Is stopping after a tested, independently reviewed Draft PR the required automation boundary?
2. Who is the authenticated human owner for the future plan-approval integration?
3. Which AI platforms need team files now, even though live accounts will remain disabled?

## Recommendation

Recommend a governed software team because the requested work must survive restarts and bind implementation to exact human approval. Explain the persistent controller, revisions, leases, evidence, recovery and Draft PR stop. The internal mapping is `software-managed`.

Alternative: an AI-assisted file team is simpler when a person coordinates every handoff.

Not enabled by creation: real feedback channel, OpenClaw bindings, model account, remote identity, GitHub write identity, production sandbox, merge or deploy. The generated team is a validated control package and reference runtime, not a silently running service.

## Confirmation stop

The plan preview must list all disabled live adapters and the exact new team path. Confirmation authorizes local creation only. Connecting feedback, models, SCM and Runner remains a later integration project with separate scope, identities, recovery and negative tests.
